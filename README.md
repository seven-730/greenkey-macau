# 绿钥 GreenKey · 澳门文旅中小微企业运营性碳减排核证平台

> 绿色不该由发票定义，而该由用电曲线定义。

一套为**澳门持牌小型酒店、经济型酒店、青年旅舍与小餐饮**设计的 AI 驱动型「未被核算碳减排潜力」评估平台。
对应「可持续能源」主题下的**能源消耗**维度：把日常经营行为形成的节能，转化为可视化、可验证、且有财务价值的指标。

### 中英文切换

导航栏右侧有 **中 / EN** 切换器，**默认中文**。

- 选择会被记住（`localStorage`），站内跳转保持同一语言；
- 也可用链接直接指定：`index.html?lang=en` 进英文，`?lang=zh` 回中文；
- 全站 1,030 条文案逐条翻译，覆盖七个页面、交互演示、图表标签与开机序列；
- 切换即时生效，不需要刷新；切回中文时原文逐字还原（不是二次翻译）。

实现方式：`assets/lang/en-1..4.js` 存放按页分片的词典，`assets/i18n.js` 在 DOM 上做文本节点替换，
并为演示页这类由 JS 生成的动态文案提供 `GK.t("中文","English")` 助手。
词典键做了引号字形归一化，源码里中英文引号混用也能命中。

## 三、一句话讲清楚

> 现行绿色金融衡量的是**资本投入**，不是**碳**。
> 小酒店在普通工作日关掉一层楼、缩短营业、降低负荷——减排真实发生，却因为没有一张设备发票而被挡在门外。

三段式论证：

1. **结构**：澳门 2024 年接待旅客 3,493 万人次（+23.8%），但小微酒店的能耗不随"淡旺季"变化，
   而是随**节假日与普通工作日**剧烈波动。工作日入住率常低于 40%，公众假期接近满房。
2. **错配**：贴息上限 MOP 500 万、期限最长三年，条件却是"有发票的资本密集型改造"。
   真正在做运营节能的小微企业，拿不出这张发票。
3. **方法**：用"历史常态 / 校正 BAU"双轨基线把账单降幅拆成**活动量效应**与**强度效应**，
   只核证后者，再折算成绿信分，接入信贷与贴息。

**最锋利的那个数字**：一间 40 房精品酒店，28 天账单比历史常态低 **15.0%（4,952 kWh）**，
其中 **2,126 kWh 只是客人变少了**。不做入住率校正，会把 4,952 全记成减排——**高估 75%**。

## 四、90 秒路演脚本

> **（0:00）** 澳门 98% 以上的企业是中小微，其中约 1,800 家是持牌小酒店、青旅和小餐饮。
> **（0:12）** 它们星期一住 38%，国庆住 92%。于是在普通工作日，它们关掉一层楼、缩短营业、把设备降负荷——
> 电费真的降了，减排真的发生了。
> **（0:28）** 但银行不认。因为绿色信贷和贴息要的是发票：你买了什么设备、花了多少钱。运营节能没有发票。
> **（0:40）** 有人会说，那就给它们做个碳核算。问题是——如果拿"平均用电"当基线，
> 一家什么都没做的店，只要客人变少，就能算出减排。这不是核算，这是把生意变差奖励一遍。
> **（0:55）** 绿钥做的是双轨基线：先算"去年同期这种日子通常用多少"，再按**今天实际住多少人**校正。
> 两条线之间的差是活动量效应，扣掉；剩下的才是效率。
> **（1:10）** 同一间酒店、同一份账单：账单降了 15%，但真正可核证的只有 9.1% 的强度改善——2,827 度电。
> 少了，但这一份银行敢采信。
> **（1:20）** 它折成绿信分 723，对应 MOP 41 万授信、1.4 个百分点的利率优惠。
> **（1:28）** 两年 300 家，3,900 吨碳，MOP 1 亿授信。**我们卖的不是软件，是被制度采信的确定性。**

## 五、评委高频提问与应答

**Q1. 为什么用"工作日/节假日"，而不是"淡旺季"？**
澳门的客流是事件驱动的：黄金周、大赛车、艺术节、周末。用月度淡旺季会把"周一到周四"整段抹平，
而节能恰恰发生在这些日子里。日型是第一位的解释变量，气温是第二位的。

**Q2. 入住率下降时，你们的数字会不会跟着变好？（最尖锐的问题）**
不会。核证以**单位活动量能耗**（kWh/间夜 或 kWh/客次）为分子，入住率只影响分母。
演示页可以直接验证：把工作日入住率从 75% 拖到 15%，活动量效应急剧变大，但强度改善率只在 8.8% → 9.4% 之间微动。
这正是方法学 §6、网站 impact 页"如果按入住率给分，就等于奖励空房"那一节讲的事。

**Q3. 银行凭什么采信一套自建模型？**
① 口径保守：用校正 BAU 作被减数、P10 作门槛，宁可少算 30–45%；
② 可复算：方法学、参数快照、数据哈希公开，第三方能用同一份原始数据算出同一个数；
③ 有复核：每年 10% 随机抽样 + 20% 大额全量复核，结论写入证书状态且不可删除。

**Q4. 为什么不做碳信用 / 碳交易？**
边界不同。碳信用需要额外性论证、项目注册与买家网络，最小规模远高于单店年减排量。
我们产出的是**避免排放凭证**，用于绿色金融与政府认证的材料支持，不用于抵消声明。方法学 §9 写死了这条。

**Q5. 大厂或银行自己做一个怎么办？**
单店年成本 MOP 1 万量级，大厂的销售成本都不止这个数；银行缺的是 MRV 能力而不是系统。
真正的壁垒是**本地方法学定义权 + 协会/银行渠道 + 数据飞轮**，不是模型代码。

**Q6. 小微酒店连 PMS 都没有，数据从哪来？**
账单是唯一必选项；入住率可用订房平台后台、前台日报或营业日历代理。缺数据不会让核证失效，只会**降级**：
C 级置信区间 ±15%，同一家店核证量更小。这是"证据不足就少算"的机械实现。

**Q7. 单店成本 MOP 1 万，小酒店愿意付吗？**
服务费设计为**可核证节能收益的 20–30%**（MOP 8,000–15,000/年），首年可完全按效果付费——
企业不先掏钱，从省下来的电费里分成。300 家规模时单店年化成本约 MOP 1.01 万，刚好被这个费率覆盖。

**Q8. 如果政府不认这套方法学？**
商业路径不依赖政府认证。银行侧可以先跑（贴息 + 信保是轻路径），政府认证是加速器而不是前提。
但我们把"被制度吸收"写成了第 3 条成功条件——因为那才是这件事真正做成的标志。

**Q9. 为什么先做澳门？**
城市尺度小到可以跑完"企业—银行—政府"的完整闭环，又密到一家商会就能触达上千家门店。
这是唯一能在 24 个月内验证整套制度假设的地方。

**Q10. 团队呢？**
概念阶段。所需能力按"四种必须同时在场"列出（旅游管理 / 时序建模 / 碳核证 / 绿色金融），
决赛材料补充履历与顾问确认函。我们不假装已经有了。

## 七、开机序列（层层解锁）

首次进入站点时，会播放约 **2.8 秒**的开机动画：

1. 网格底纹缓慢漂移，一条扫描线自上而下扫过；
2. 系统框架带四角括号淡入，顶部显示 `绿钥 / GREENKEY OAR ENGINE` 与闪烁光标；
3. **四层依次解锁**，与平台架构一一对应：

   | 层 | 名称 | 解锁后显示 |
   |---|---|---|
   | 01 | 数据采集 DATA INGEST | 4 SOURCES · 15MIN |
   | 02 | 双轨基线 BAU MODEL | 28 DAYS · P10 0.94 |
   | 03 | 验证核证 VERIFICATION | OAR 2,827 kWh |
   | 04 | 金融联动 FINANCE | GCS 723 · MOP 410K |

   每层从 `LOCKED` 翻成 `UNLOCKED`，底部进度条点亮一段；
4. 左侧日志流同步滚动（校验授权 → 接入数据 → 拟合基线 → 剔除活动量效应 → 签发凭证）；
5. 四层全开后闪出 `SYSTEM READY`，遮罩淡出，页面内容上浮进场。

**控制方式**

- 只在会话内首次播放（`sessionStorage`），页面间跳转不会重复打断；
- 随时可点右下角 `跳过 SKIP` 或按 `Esc` 跳过；
- `?boot=1` 强制重播（路演时可用来给评委演示），`?boot=0` 跳过；
- `prefers-reduced-motion` 用户自动跳过；
- 脚本加载失败有 3.5 秒兜底，不会把页面锁在黑屏里。

## 八、设计说明

- **深色科技风（Climate-tech console）**：近黑底 `#05090B` + 72px 细网格 + 两处冷光；
  电光薄荷 `#2BE8A6` 只用于"已核证/可交互"的东西，赭橙 `#E8825A` 只用于"不该被计入"的东西。
  颜色在这里是有语义的，不是装饰。
- **全站无衬线 + 等宽仪表**：标题用 Inter / Noto Sans SC 800，数据与标签用 JetBrains Mono，
  形成"仪表盘读数"与"叙事"两种语体。
- **一处刻意保留的纸**：凭证卡片仍是米白纸张 + 宋体。它是整个数字系统唯一的"物理产物"——
  在深色界面上出现一张纸，比再多发光效果都更像一件事已经发生了。
- **图表按容器真实像素渲染**（viewBox 宽度 = 容器宽度），文字在任何栏宽下都是实际字号，不会被缩放糊掉。
- **数字不做动画**：所有统计数字直接落到终值——论据不该停在中间帧。
- **可访问性**：正文对比度 ≥ 4.5:1、语义化标签、`aria-pressed` 状态、键盘可达、
  `prefers-reduced-motion` 降级、打印样式（深色界面会打印成白底）。

## 九、部署到公网

整个 `greenkey` 文件夹就是一个完整站点，**无需构建、无需 Node、无后端**。三种常见方式：

**A. GitHub Pages（推荐，地址固定）**

在 `default-workspace` 目录下执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\_deploy.ps1 -Token ghp_你的令牌
```

脚本会建仓库 `greenkey-macau`、上传全部文件、开启 Pages，并轮询到上线，最终打印
`https://你的用户名.github.io/greenkey-macau/`。令牌只需 `repo` 权限，用完记得撤销。

**B. Netlify Drop（不用命令行，30 秒）**

打开 `https://app.netlify.com/drop`，把整个 `greenkey` 文件夹拖进去，得到 `https://xxx.netlify.app`。
之后可在 Netlify 后台改子域名、绑自定义域名、看访问统计。

**C. 任意静态托管**

Vercel / Cloudflare Pages / 学校服务器均可：把 `greenkey` 里的文件传到站点根目录即可。

部署后须知：

- 所有资源路径都是**相对路径**，放在子目录（如 `/greenkey-macau/`）也能正常工作，已用本地服务器在子路径下验证过全部 16 个资源；
- `.nojekyll` 已放置，GitHub Pages 不会走 Jekyll 预处理；
- `?lang=en`、`?boot=1` 这些参数在公网地址上照常生效，可直接用于评审引导；
- 已配置 Open Graph / Twitter 卡片，链接分享到微信、Slack、邮件时会显示标题与摘要。

## 十、已知取舍

1. 案例企业（廖先生、40 房精品酒店）为**虚构**，用于方法演示，不构成任何真实企业的数据披露。
2. 表 1 市场规模、表 3 成本、表 4 目标均为**团队估算**，页面已明确标注"待试点核实"。
   正式参赛材料建议补一份数据来源附录（澳门统计暨普查局、旅游局、立法会书面答复等）。
3. 排放因子、电价取公开区间参考值，**未逐项引用官方文件**。
4. 交互演示为前端确定性模型，不含真实机器学习训练过程；分位数部分以参数化形态实现，用于说明机制而非复现精度。
5. 历史常态采用固定基准年以抑制漂移，代价是基准会随产业周期逐渐过时——这一条写进了方法学 §9。
